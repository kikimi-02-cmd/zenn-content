## 「毎朝動いているはず」のジョブが、実は動いていなかった

個人開発で、毎朝定時に走らせている GitHub Actions の cron がありました。データを集めて、整形して、コミットする。半年くらい「順調に回っている」と思っていました。

ある日たまたま出力ファイルの日付を見て、血の気が引きました。**最終更新が3週間前**で止まっていたんです。エラー通知も来ていない。ワークフローは「成功（緑）」のまま。なのに、中身は更新されていなかった。

> 動いている、ではなく、動いているように見えていただけだった。

同じように「無人で回しているつもりの自動化」を持っている人、これは他人事じゃないかもしれません。

## 何が起きていたのか

原因は2つ重なっていました。

### 1. スケジュール実行が勝手に止まる仕様
GitHub Actions の `schedule`（cron）は、**リポジトリが60日間 push されないと自動で無効化される**仕様があります（公式仕様）。「完成して放置」のリポほど踏みます。

### 2. 「成功」の定義が間違っていた
より痛かったのはこっち。ジョブは最後まで例外を投げずに終われば「成功（緑）」になります。でも私のスクリプトは、**取得元が空を返してもエラーにせず、空のまま正常終了**していました。つまり「0件を正常に処理した」状態。CI は緑、通知も無し、中身はゼロ。

これが一番こわい失敗の形です。**落ちてくれれば気づける。緑のまま死ぬと気づけない。**

## 真因：失敗を「例外」だと思い込んでいた

私はずっと「失敗 = エラーで止まること」だと思っていました。だから「エラーが来ない = 大丈夫」と考えていた。

でも実際の失敗は、**例外を投げない失敗**でした。「期待した仕事をしていないのに、成功と報告される」。監視していたのは「落ちたか」だけで、「**ちゃんと仕事をしたか**」を一度も見ていなかった。

## 防止装置：3つ入れた

### ① cron の生存を別ジョブで監視（heartbeat）
出力ファイルの最終更新が古かったら落とす、独立した見張りを足しました。落ちれば通知が飛ぶ。

```yaml
# .github/workflows/heartbeat.yml
on:
  schedule:
    - cron: "0 22 * * *"   # 本体ジョブの後に走らせる
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Fail if output is stale (>24h)
        run: |
          if [ -z "$(find output -name '*.json' -mtime -1)" ]; then
            echo "::error::output stale > 24h"
            exit 1
          fi
```

### ② 「成功」の定義に“中身”を入れる
スクリプト側で「黙って0件成功」をやめ、空を失敗として扱うようにしました。

```python
items = fetch()
if not items:
    # 空が正常な日もあるなら条件を絞る。少なくとも"沈黙の0件成功"はやめる。
    raise SystemExit("fetched 0 items — treat as failure, not silent success")
```

### ③ 失敗時に必ず自分へ通知
緑のときは黙る、赤のときだけ鳴らす。

```yaml
      - name: Notify on failure
        if: failure()
        run: |
          curl -s -X POST "https://api.telegram.org/bot${{ secrets.TG_TOKEN }}/sendMessage" \
            -d chat_id="${{ secrets.TG_CHAT }}" \
            -d text="⚠️ ${{ github.workflow }} failed: ${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}"
```

## 学び：監視すべきは「落ちたか」ではなく「仕事をしたか」

半年分のデータを取り損ねた授業料で学んだのはこれです。

> 無人の自動化で本当にこわいのは、エラーで落ちることではなく、**緑のまま何もしていないこと**。

「動いているはず」を「動いた証拠があるか」に変える。それだけで、静かに死ぬ自動化はかなり減ります。同じ罠の前にいる人へ届けば。
